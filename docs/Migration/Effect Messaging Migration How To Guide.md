# Effect Messaging Migration How-To Guide

Scratch doc for the wave of agents bringing `slices/*/<slice>-expo` packages
from `ruthmarks/add-wildflower-expo` into `main`. **Delete after the
migration wave lands.**

## Premise

The revert commit on the branch (`6f71f65`) claimed main "supersedes
`HostBinding` with `makeBridgeDispatcher` / `makeMessageSenderPipe`."
**That is wrong.** Main keeps `HostBinding` (in `effect-messaging-core`)
and uses it from `effect-messaging-expo/BridgedWebView`. Both patterns
coexist on main:

| Layer                 | Pattern on main                                                                       |
| --------------------- | ------------------------------------------------------------------------------------- |
| Host shell wiring     | `HostBinding<B>` tuple → `BridgedWebView bindings={…}` (still the contract)           |
| In-tree dispatch      | `makeBridgeDispatcher` (slice provider + `useAsMessageHandlers` + `useMessageSender`) |
| Pipe across providers | `makeMessageSenderPipe` (registers a transport sender into a React context)           |

So `use<Slice>HostBinding` hooks on the branch translate **almost 1:1** onto
main. Don't rewrite them.

## What the branch had vs. what main has

| `effect-messaging-core` symbol  | Branch (post-revert)                     | Main                                                                            | Migration impact                                                                          |
| ------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `HostBinding` namespace         | **deleted**                              | exported (`aggregate`, `callTransportReady`, `HostBinding<B>`, `Any`)           | None — branch's slice files already import the right symbol; the import resolves on main. |
| `BareSender`                    | type alias inside `transport-adapter.ts` | `Context.Tag` class in its own `bare-sender.ts` + `BareSenderService` interface | None for slices; only matters if you mock the transport.                                  |
| `Bridge.UrlParamableMessage`    | tag keys could be `undefined`            | `-?` modifier strips `undefined`                                                | Stricter — `initialMessages` literals still type-check.                                   |
| `BridgeTransport.MessageSender` | `out` variance on `Bridges`              | invariant                                                                       | Cosmetic.                                                                                 |

`fc.webPath()` already exists at `global/effect-messaging/effect-messaging-react/src/test-utils/test-arbitraries.ts` on main with no drift. Tests using it work as-is.

## Migration recipe (per `-expo` slice)

1. Create a new worktree via `.devcontainer/wf-worktree.sh new ruthmarks/migrate-<slice>-expo main`.
2. **`git diff main <source-commit> -- slices/<slice>/`** _before_ copying. Main has already absorbed earlier PRs from this wave (e.g. #60 `LocalClientToken`); reading the diff this way exposes the truly-new files instead of regressing main. **Correction:** the prior gatekeeper-expo note claimed PR #58 landed `use-gatekeeper-host-messaging` / `HostMessagingProvider` on main — that is wrong. Those helpers (`makeUseHostMessaging`, `HostMessagingProvider`, `HostMessaging` / `HostToWebMessage` types) **do not exist on main** and were never merged. The collector-expo PR replaced the need for them with per-slice `makeMessageSenderPipe` instances — see `slices/collector/collector-expo/src/message-sender-pipes.tsx` for the worked example. Look for three buckets:
   - **Pure additions** on the source commit → copy as-is (e.g. new test files, `host-receiver-layer.ts`, `use-host-binding.ts`).
   - **Files where main is ahead** → keep main's version (it's the result of review). The source commit may pre-date a split/rename — don't reintroduce a merged file.
   - **Files where main and the source disagree** → judgment call; prefer main unless the source has a real new behaviour main doesn't.
3. Copy the pure-addition files from the source commit using `git show <source-commit>:<path>`. Source commits used so far: `ruthmarks/add-wildflower-expo` (navigation-expo), `70479f8` ad-hoc tip (gatekeeper-expo).
4. Run `vp install` in the worktree (auto-runs from `wf-worktree.sh new`).
5. **Run `vp run pack`.** Workspace packages declare `exports['.'].default = "./dist/index.js"`; jest's resolver follows `exports` first and can't find the dep until each package's `dist/` exists. The main checkout already has built `dist/`s — fresh worktrees don't, hence the extra step.
6. Run `vp check` (workspace-wide) and `cd slices/<slice>/<slice>-expo && vp run jest`. Also run `vp test` on `<slice>-core` and `<slice>-react` if you added tests there.
7. Patch only the things check/jest surfaces. Do **not** preemptively rewrite to `makeBridgeDispatcher` — `HostBinding` is fine.
8. Commit, push, open a PR titled `feat(<slice>-expo): port from add-wildflower-expo`.

## Cumulative findings (read before starting the next slice)

- **Build before jest in fresh worktrees.** The first-time miss above is the biggest time-sink.
- **Trust `<slice>-core` over branch handlers.** Whenever a `<slice>-expo` handler in the branch destructures a key the core schema doesn't have, the schema wins. The branch's `-expo` packages never type-checked, so they're not authoritative — they're _candidates_.
- **Tests using `Effect.logDebug`** must lift `minimumLogLevel`. Worth adding a tiny helper if multiple slices need it; for now each slice can inline `Logger.withMinimumLogLevel(LogLevel.All)` per the recipe above.
- **`vp check --fix`** is safe to run after copying — the branch's formatter settings drift slightly from main's.
- **Diff main vs source first** (recipe step 2). As the wave progresses, more of each branch's content has already been merged in pieces. For gatekeeper-expo the whole `gatekeeper-react/` directory was already ahead of `70479f8`; only the `-expo` adapter files were truly new. Skipping the diff would have regressed `wait-for-host-token-ref.ts` and `use-gatekeeper-host-messaging.ts`.
- **`HostBinding.BindingSend` doesn't exist on main.** Drop the type annotation on the `send` callback inside `useMemo` — contextual typing from the returned `HostBinding.HostBinding<typeof Bridge>` gives `send` the correct shape (see fix-up table).
- **Source commits diverge per slice.** `navigation-expo` came from `ruthmarks/add-wildflower-expo`; `gatekeeper-expo`, `browser-sniffer`, and `collector-expo` from `70479f8`. Confirm the source commit with the user before assuming the recipe's default.
- **Log is now its own `LogBridge` in `effect-messaging-core`.** Future `-expo` slices should NOT add a `Log` tag to their own bridge — wire `useLogHostBinding()` from `effect-messaging-expo` into the host shell's bindings tuple instead. The hook defaults its handler to `LogBridge.defaultOnLog` (routes through the Effect logger at the matching level), so most callers need no boilerplate.
- **A source-commit removal may have a fresh consumer on main.** PR #74 merged after the source commit branched and added `collector-expo/src/screens/RunSyncModalScreen.tsx` consuming the very surface the source commit later deleted (`BrowserSnifferWebView.postRaw` / `onRawMessage`). **`grep -r` the whole repo for the to-be-removed symbol — don't trust a slice-local search**, especially when the parent shell was on a different branch (the original PR almost shipped with a regressing port because the grep ran in the parent worktree's branch, not the worktree being edited).
- **Empty packages need `passWithNoTests: true`** in `jest.config.cjs`, or the workspace-wide `vp run -r jest` exits 1. Likewise oxlint rejects `export {}` as a placeholder — use `export type Placeholder = never` (or similar) so the lint passes and consumers still resolve the module.
- **Rebase against `origin/main`, not local `main`.** Local refs go stale fast when the migration wave merges several PRs an hour. Run `git fetch origin main` and compare `git log HEAD..origin/main -- <area>` before sizing the diff.
- **When a `-expo` adapter wraps a generic primitive,** prefer thin composition (slice owns the props it needs, generic owns the transport plumbing). `BrowserSnifferWebView` is now ~80 lines of binding wiring + ref forwarding on top of `BridgedWebView`. The pattern: build a `HostBinding` for the slice's bridge with `onTransportReady: (send) => Effect.sync(() => { senderRef.current = send })` to capture the typed sender, expose it via `forwardRef` as a stable `Effect.suspend`-wrapped callback. Pre-mount messages drop with a logged error rather than silently — loud failures beat invisible ones.
- **Pre-existing flaky property tests in `fhir-r4` (`bundle.test.ts`) and `store-core` (`observation.test.ts`)** time out at 20s in fresh worktrees on slow Docker. These are unrelated to the migration; if your slice's tests pass cleanly, surface the flake to the user rather than chasing it.
- **`70479f8` carries diagnostic noise.** Its own commit message admits `console.debug(...)` calls in `CollectorModalScreen` were debugging aids; strip them on copy. Same applies for any future `70479f8`-sourced port.
- **Branch can be _behind_ main on shared utilities.** `collector-react/screens/account-list.tsx` on `70479f8` inlines a cause-unwrap that became `unwrapCause` in `react-kitchen-sink` after the branch was written. Keep main's version. Run `git diff main..<source> -- <file>` for any file that looks small and suspiciously "manual" — it may be an inlined version of a helper that landed later.
- **Some branch diffs are intentional design swaps, not regressions.** `fhir-r4-client-collector/config.ts` on `70479f8` drops `baseUrl` and uses `credentials: 'omit'` to dodge CORS preflight at the cost of cookie auth. Main keeps cookie auth. Surface this kind of disagreement to the user; the new docstring on the branch usually explains the swap.
- **`HostMessagingProvider` / `useHostMessaging` were branch-only inventions** — they don't exist on main. When a slice needs a host-side outbound `MessageSender` mid-tree (i.e. the host component tree needs to dispatch a typed message into an embedded WebView's bridge), the resolution is per-slice `makeMessageSenderPipe` instances fed by the typed `MessageSender` each WebView exposes through its ref. The collector-expo PR worked this pattern end-to-end: see `slices/collector/collector-expo/src/message-sender-pipes.tsx` for the two-pipe example (`[BrowserSnifferBridge]` host→sniffer-page + `[CollectorBridge]` host→collector-SPA), with both `Provider`s mounted by a single `HostProvider`. `gatekeeper-expo` and `navigation-expo` didn't need this because their host sides only _receive_; `collector-expo` did because `CollectorModalScreen` re-emits sniffer events into the SPA's `CollectorBridge`.
- **Handlers reply via `bridge.send(...)` directly.** `HandlersFor` widens to `Effect<void, never, TransportAdapter>`; the dispatch fiber discharges `TransportAdapter` per-invocation under the transport's own adapter, so a handler can route a reply through the same-bridge sender with no intermediate ref. Test sites that run handlers in isolation (e.g. `Effect.runPromise(handler.X(...))`) must provide a `TransportAdapter` layer — use `TestPlatformAdapterLayer.make().layer`. See `apps-expo` (`host-receiver-layer.ts`) and `apps-expo/src/host-receiver-layer.test.ts` for the pattern. `browser-sniffer-expo` still owns a `MessageSender` ref because its `forwardRef` surface exposes one externally to consumers — that's separate from the handler reply path.
- **`useAppsHostBinding`'s `tunnelStoreLayer` prop is a one-off.** Every other host-binding hook on main takes either config callbacks (`useNavigationHostBinding`), a token-bag (`useGatekeeperHostBinding`), or nothing (`useCollectorHostBinding()` pulls state from `CollectorHostProvider` via React context). `useAppsHostBinding` takes a `Layer<TunnelStore>` because no React-side `TunnelStore` provider exists on main — the host shell still has to wire `TunnelStore.layerFrom(store)` itself and pass it in. The context-based shape remains preferred whenever a provider is available; only reach for the layer-prop pattern when there isn't one. (Note: callers must memoize the layer — the hook's `useMemo` dep list compares by reference.)
