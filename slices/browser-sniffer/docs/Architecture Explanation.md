# Browser Sniffer — Architecture Explanation

## What this slice is

A page-sniffing primitive. Four packages:

- **`browser-sniffer-core`** — the pure contract: the message schemas (the six events the sniffer emits), `BrowserSnifferBridge` / `CollectorBridge` declaring them, the `WebViewSource` union, and the `/sniffer` `HttpApi` definition with its `openapi-drift` test. Transport-agnostic; the piece a non-Tauri consumer reuses.
- **`browser-sniffer-tauri`** — the sniffer body (`installSniffer(eventBus)`, which shims `window.fetch` / `XMLHttpRequest` / `console` and emits captured network activity as structured payloads on the single multiplexed `BRIDGE_EVENT` channel with `_tag` as the dispatch discriminator) plus the IIFE wrapper that runs as the webview's initialization script. Bundles to a self-contained IIFE (`dist/tauri-bootstrap.js`, regenerated by `vp install`) which the Rust crate includes via `include_str!`. See [Tauri Host Explanation](./Tauri%20Host%20Explanation.md) for the full plumbing.
- **`browser-sniffer-rust`** — the slice's HTTP surface (pure Axum, no Tauri): the `/sniffer` control endpoints and the `/sniffer/events` WebSocket, the `wildflower/Sniffer.{c,r}` scope-gated capabilities, the `SnifferWebviewHandle` port, and the `SnifferEvents` broadcast stream. Owns the committed OpenAPI snapshot.
- **`browser-sniffer-tauri-rust`** — the Tauri host adapter behind those two ports: `TauriSnifferWebviewHandle` drives the native webview through `tauri-plugin-native-webview`, and the page→host data-plane gate publishes validated page events (plus the synthesized `UserDismissed` / `SnifferDisposed` lifecycle events) into `SnifferEvents`. It also injects the bootstrap as the webview's initialization script.

No package in this slice knows about FHIR, collector, or any specific consumer. The schemas are a primitive other slices compose with.

## What the sniffer captures

When `installSniffer(eventBus)` runs in a page, it:

1. Shims `window.fetch` and `XMLHttpRequest` so every response surfaces as a sequence of:
   - `ResponseStart { id, url, status, statusText, headers }`
   - One or more `ResponseData { id, data: base64 }` chunks
   - `ResponseFinished { id }`
2. Reports `RequestError { id, url, message }` on network failure or abort (fetch reject, XHR `error`/`abort` events). Each terminal is preceded by a `ResponseStart` — synthesized with `status: 0` and empty headers when the failure happened before response headers arrived — so the host-side `RequestError` / `Cancelled` handlers always see a Start before a terminal (they drop a terminal for an untracked id). An XHR `abort` reports `RequestError` rather than `ResponseFinished`: the body is partial, so it must not be parsed as complete.
3. Posts `PageLoaded { url, pageContentId }` once the page has **settled**, then streams the DOM body through the standard `ResponseStart` / `ResponseData` / `ResponseFinished` triple correlated by `pageContentId`. Settlement — not the raw window `load` event — gates the snapshot: on `load` the sniffer starts a watch (a `MutationObserver` plus the in-flight-request count) and fires `PageLoaded` only once the DOM has stopped mutating _and_ no fetch/XHR is in flight for a continuous quiet window (`SETTLE_QUIET_WINDOW_MS`, default 1 s), or a hard ceiling elapses (`SETTLE_MAX_WAIT_MS`, default 10 s) so a page that never fully quiesces — a long-poll, a perpetual spinner — still completes. Because the snapshot is taken post-settlement, an SPA's rendered DOM is captured rather than the near-empty shell present at `load`. The two thresholds are overridable per install via `installSniffer`'s `options.settle` (tests pass small values to drive the watcher deterministically); the bootstrap entries pass none and get the defaults. A JSON-viewer readiness guard (WebKit builds `<pre>{json}</pre>` a frame or two after `load`) additionally blocks an early fire for JSON content types until the `<pre>` renders.
4. Posts ad-hoc `Log { log }` entries when shims install (single-shot diagnostics).
5. Accepts host→web `PageAction` and `CancelSnifferRequest` messages via a single `eventBus.listen(BRIDGE_EVENT, …)` registration that demuxes by the payload's `_tag`. `PageAction` is the single scripted-interaction tag — its inner `action.kind` (`Click` / `Fill`) selects the in-page effect, so a new interaction kind is a union variant rather than a whole new tag. No `window.message` indirection — Tauri's IPC is the only thing that can invoke this listener, so page scripts can't spoof inbound messages.

Idempotent: re-injecting on the same page short-circuits each shim on its `window.native*` shadow. On re-injection the previous run's listener unlistens are drained from the symbol-keyed state slot before the early-return, so the Rust-side listener registry doesn't accumulate stale IDs.

## Why a separate slice

The sniffer is **upstream** of collector (and any future scraper). It has no opinions about what the captured responses _mean_ — that's the consumer's job. Splitting it out means:

- The injected JS can evolve (new shims, new event types) without touching collector.
- A future scraper (e.g. one that consumes scraped emails or a different web app's API) can reuse the same primitive without inheriting collector's FHIR-shaped abstractions.
- Tests for the sniffer mechanics (chunk reconstruction, base64 round-trip, XHR reuse guards) live next to the code they exercise instead of leaking into a downstream package.

The slice rule says "slices should not depend on other slices unless intrinsic — document why if you do." Collector depends on browser-sniffer intrinsically: collector is built around consuming sniffer events. That dependency direction is one-way (browser-sniffer knows nothing about collector).

## Data flow in the wider system

The sniffer's message contract is `CollectorBridge` (declared in `browser-sniffer-core`, re-exported through `collector-fundamentals/bridge`), but since the Tauri→Axum migration it no longer rides a `BridgeTransport`: the client→host half is the `/sniffer` REST surface and the host→client half is the `/sniffer/events` WebSocket, both served by `browser-sniffer-rust`. Any HTTP client holding `wildflower/Sniffer.{c,r}` — the on-device SPA, or a browser reaching the phone through the tunnel — can drive a run.

```text
[collector-react SPA (or any scoped HTTP client)]
    │ user taps "Import Now"
    │ makeHttpCollectorTransport: connect GET /sniffer/events (WebSocket),
    │ then POST /sniffer/webview { source }
    ▼
[browser-sniffer-rust — the /sniffer router]
    │ scope-gates the call (Scoped<SnifferDriver>), validates the WebViewSource,
    │ and calls the SnifferWebviewHandle port
    ▼
[browser-sniffer-tauri-rust — TauriSnifferWebviewHandle]
    │ tauri-plugin-native-webview open_url(...) with browser-sniffer-tauri's
    │ bootstrap as the document-start init script, then show()
    ▼
[sniffer native webview]
    │ the bootstrap builds a TauriEventApi-shaped bus over the page's only
    │ sanctioned outbound path (the mobile native bridge, or desktop's gated
    │ native_webview_data_plane_emit command) and hands it to installSniffer
    │ installSniffer shims fetch / XHR / console and emits
    │ ResponseStart / ResponseData / PageLoaded / etc. on that bus
    ▼
[browser-sniffer-tauri-rust — the page→host gate]
    │ allowlists the inner `_tag` to the data-plane set (control and lifecycle
    │ tags are rejected), then publishes into SnifferEvents
    ▼
[browser-sniffer-rust — GET /sniffer/events]
    │ one socket, all tags, in publish order (cross-tag FIFO is load-bearing)
    ▼
[the client's CollectorBridgeMessageHandler]
    │ feeds events into a FhirR4Remote (or other Remote) for parsing
    │ writes resources via PUT /fhir-r4/*
```

The host does no parsing: `PageAction` / `CancelSnifferRequest` are re-serialized from their typed bodies and forwarded into the page verbatim via `evaluate_js`, and captured page events are published byte-for-byte as the page emitted them. See the [Tauri Host Explanation](./Tauri%20Host%20Explanation.md) for the full control/data split.

## Why a build-time bundle

`installSniffer` is esbuild-bundled to a self-contained IIFE at build time by `scripts/build-tauri-bootstrap.mts`, written into committed-on-CI / gitignored-locally files in `dist/`, and re-exported as the `tauriSnifferBootstrapScript` string. The Rust host adapter `include_str!`s those bytes into the webview's initialization script.

This places a constraint on the function: **no module-scope dependencies**. Every helper, every type-erased reference, every cross-call piece of state must live inside the function body. Top-level value imports or closures over module scope would resolve to nothing in the injected page. See `install-sniffer.ts` for the precise guardrails.

## What's deliberately not here

- **Effect-Messaging Web side**: The sniffer runs in _arbitrary_ third-party pages — it can't depend on our SPA bundle's `WebPlatformAdapter`. So it speaks the wire format manually (`void eventBus.emit(BRIDGE_EVENT, msg)` with the message's `_tag` as the dispatch discriminator) and the host decodes it through `BridgeTransport`'s `Host` side only.

- **A Tauri-shaped Web platform adapter inside the sniffer page**: the sniffer page is a _third-party_ origin; it can't import our SPA bundle or `@tauri-apps/api` runtime at build time. The desktop bootstrap relies on `withGlobalTauri: true` for `window.__TAURI__.core.invoke` alone (its outbound rides the gated data-plane command; its inbound rides the host-installed `window.__nativeWebviewReceive`), the mobile bootstrap uses the plugin's native bridge and never sees `__TAURI__` at all — and everything else runs as plain script: no SDK, no Effect runtime, no schema decoder. The structural `TauriEventApi` interface from `effect-messaging-tauri` is the only thing the sniffer body type-imports.

- **A web-side test harness for the bundled string**: jsdom tests in `browser-sniffer-tauri/tests/install-sniffer.test.ts` exercise `installSniffer` directly against a fake `TauriEventApi` recorder; `browser-sniffer-tauri/tests/bootstrap.test.ts` round-trips the bundled IIFE through `new Function(tauriSnifferBootstrapScript)()` to guard against bundle-loss of semantic information.

## Where to look next

- `browser-sniffer-core/src/bridge.ts` — the typed contract.
- `browser-sniffer-core/src/messages.ts` — the six event schemas.
- `browser-sniffer-tauri/src/install-sniffer.ts` — the shimming code.
- `browser-sniffer-tauri/src/tauri-sniffer-entry.ts` — the IIFE wrapper that gates on `__TAURI__`, injects the `BrowserTopBar`, and hands `event` to `installSniffer`.
- `browser-sniffer-rust/src/http/routes/` — the `/sniffer` control endpoints and the events WebSocket.
- `browser-sniffer-tauri-rust/src/webview_handle.rs` — the Tauri implementation of the `SnifferWebviewHandle` port (open / navigate / status / show / dispose / forward-to-page).
- `slices/collector/collector-fundamentals/src/bridge.ts` — the consumer-side bridge; re-uses message schemas from `browser-sniffer-core` so the wire format stays in lockstep.
