# AGENTS.md — slices/browser-sniffer

Page-sniffing primitive: shims `fetch`/`XHR`/`console` inside arbitrary third-party pages and streams captured activity to the host. Read the [Architecture Explanation](./docs/Architecture%20Explanation.md) before changing anything here.

## Package roles

- **`browser-sniffer-core`** — the pure contract: the sniffer message schemas (`messages.ts`), the `WebViewSource` union (`web-view-source.ts`, which the collector re-exports through `collector-fundamentals/model`), the `BrowserSnifferBridge`/`CollectorBridge` message declarations, and the `/sniffer` `HttpApi` definition (`http-api-definition/`, with its `openapi-drift` test).
- **`browser-sniffer-rust`** — the slice's **HTTP surface** (pure Axum, no Tauri): the `/sniffer` control endpoints + the `/sniffer/events` WebSocket. Exposes the `SnifferWebviewHandle` port trait and the `SnifferEvents` broadcast stream; the host implements the port and publishes events into the stream. Owns the committed OpenAPI snapshot.
- **`browser-sniffer-tauri` / `browser-sniffer-tauri-rust`** — the Tauri host adapter: the injected-sniffer bootstraps (TS) and the `TauriSnifferWebviewHandle` port impl + the page→host data-plane gate (Rust).

## Guardrails

- **`installSniffer` must have no module-scope dependencies.** It is esbuild-bundled to a self-contained IIFE and injected into pages — top-level imports or closures over module scope resolve to nothing at runtime. Every helper lives inside the function body. See `browser-sniffer-tauri/src/install-sniffer.ts` for the precise rules.
- **Never hand-edit generated bootstrap files.** `browser-sniffer-tauri`'s `dist/tauri-bootstrap.js`, `dist/native-bootstrap.js`, and the `src/*-bootstrap.generated.ts` twins are regenerated by the package `prepare` script (`scripts/build-*.mts`, runs on `vp install`); the Rust crate `include_str!`s the dist bytes.
- **The `/sniffer` surface is scope-gated but NOT auth-gated in-slice.** `browser-sniffer-rust`'s router carries no middleware; the composition site (the Tauri host) wraps it with `layer_router_with_gatekeeper_auth_gating`. Each op is scope-gated per operation (`wildflower/Sniffer.c` control plane, `.r` event stream) via `Scoped<…>`; an unwrapped router fails closed with a 500.
- **The client→host surface is HTTP, but the page→host data plane is NOT.** A sniffed third-party page must never gain an HTTP path to the host — it stays behind the mobile channel allowlist (`validate_native_webview_message`) / desktop gated command (`native_webview_data_plane_emit`), which publish into `SnifferEvents`. Only the host→client re-broadcast moved off the Tauri bus onto the WebSocket.

## Traps

- There are **two bootstrap variants** (Tauri desktop vs native/mobile) built from separate entries — a change to the sniffer body usually affects both.
- **Two drift surfaces pin the wire, and they must move together:** the OpenAPI snapshot (`browser-sniffer-rust/openapi/browser-sniffer.openapi.json` ↔ `browser-sniffer-core`'s `openapi-drift` test) for the REST control plane, and the event-tag literals (`browser-sniffer-rust`'s `domain::events` constants ↔ `messages.ts`, drift-guarded by `native_webview_bridge::tests::data_plane_tags_match_ts`) for the WebSocket stream. Regenerate the snapshot with `UPDATE_OPENAPI=1 cargo test -p browser-sniffer-rust openapi_spec_snapshot_is_up_to_date`.
- The data-plane vs control capability split is enforced at the transport layer, not by event naming — see the [Tauri Host Explanation](./docs/Tauri%20Host%20Explanation.md).
