## Default Permission

Default grant for the native-webview plugin: navigate a native webview to an
external URL (`open_url`), evaluate JS inside it (`evaluate_js`), patch its
title / subtitle / message chrome labels (`patch_window_text`), present it
(`show`), hide it while keeping it alive (`hide`), and tear it down
(`dispose`). Each references a hand-authored, richly-described per-command
permission file (`open-url.toml`, `evaluate-js.toml`, `patch-window-text.toml`,
`show.toml`, `hide.toml`, `dispose.toml`) rather than the boilerplate
autogenerated `allow-*` grants.

#### This default permission set includes the following:

- `open-url`
- `evaluate-js`
- `patch-window-text`
- `show`
- `hide`
- `dispose`

<td>

`native-webview:dispose`

</td>
<td>

Allow disposing the native webview — tearing it down (visible or hidden) and
freeing its resources. Emits the `disposed` channel event. Idempotent —
succeeds as a no-op when nothing exists.


</td>
</tr>

<tr>
<td>

`native-webview:evaluate-js`

</td>
<td>

Allow evaluating caller-supplied JavaScript inside the currently-open native
webview (e.g. the host pushing a `window.__nativeWebviewReceive(...)` bridge
message in). The script is run verbatim and not sandboxed; the call errors if
no native webview is open.


</td>
</tr>

<tr>
<td>

`native-webview:hide`

</td>
<td>

Allow hiding the native webview — removing it from view while keeping it alive
and running in the background. Emits the `hidden` channel event. Idempotent —
succeeds as a no-op when nothing is visible. Does NOT free resources; use
`dispose` for that.


</td>
</tr>

<tr>
<td>

`native-webview:open-url`

</td>
<td>

Allow ensuring a native web view exists over an external `http(s)` URL and
navigating it there: a `WKWebView` (iOS), `android.webkit.WebView` (Android), or
Tauri child webview (desktop) wrapped in native chrome, with the caller's
document-start script injected on any origin and a `Channel<NativeWebviewEvent>`
carrying message / hidden / disposed events back to the host. Navigation only —
presentation is a separate grant (`show`). Non-`http(s)` schemes are rejected.


</td>
</tr>

<tr>
<td>

`native-webview:patch-window-text`

</td>
<td>

Allow patching the native webview chrome's three text labels — title, subtitle, and the
bottom-bar message. Each field is independent: omitted = leave unchanged, empty
string = clear, otherwise set. A no-op (resolving "not set") when no native webview is
open, so the host can push speculatively across the native webview lifecycle.


</td>
</tr>

<tr>
<td>

`native-webview:show`

</td>
<td>

Allow presenting the native webview — bringing a freshly-created or
previously-hidden instance to the foreground. Visibility only; navigation is the
separate `open_url` grant. Idempotent — succeeds as a no-op when nothing exists
to show.


</td>
</tr>
</table>
